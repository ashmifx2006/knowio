# Knowio

**"Don't study more. Study what you don't know."**

An AI diagnostic learning assistant prototype that identifies hidden
knowledge gaps instead of just answering questions. Built for a college
symposium submission.

This is not a chatbot — there is no chat window anywhere in the product.
The workflow is: choose a topic → answer adaptive diagnostic questions →
get a Knowledge Mirror report (strengths, weaknesses, misconceptions,
missing prerequisites) → follow a personalized day-by-day learning path.

---

## Project structure

```
knowio/
  frontend/    React + Vite + Tailwind + React Router + Framer Motion + Recharts
  backend/     FastAPI (API structure only — mock JSON responses for now)
```

The backend is intentionally "structure only," per the brief: routes,
Pydantic models, and a MongoDB schema design (`backend/database/schema.md`)
are all in place, but every route currently returns mock data. Swapping
mock data for real DB/AI calls is a scoped, drop-in change — each route
file has `TODO` comments marking exactly where that logic goes.

---

## Running the frontend

```bash
cd frontend
npm install
npm run dev
```

Opens at `http://localhost:5173`. Every page works end-to-end with mock
data — no backend required to click through the full prototype.

## Running the backend (optional, for the API shell)

```bash
cd backend
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

The backend does **not** require MongoDB to run right now — `motor` is
listed in `requirements.txt` for when you're ready to wire up
`database/connection.py`, but no route calls it yet.

## Connecting frontend to backend later

`frontend/src/services/api.js` already contains every API call the app
needs (`login`, `getSubjects`, `submitAssessment`, etc.), each currently
resolving mock data with an artificial delay. Once the backend is live,
replace each function body with a `fetch(`${BASE_URL}/...`)` call — the
argument and return shapes already match the FastAPI routes.

## Design notes

- Theme: dark "mirror" surface, blue → purple gradient, glassmorphism cards,
  rounded corners, Space Grotesk (display) + Inter (body).
- Signature visual: a mirrored-triangle logo mark and a literal
  strength/weakness "split" panel on the Knowledge Mirror Dashboard —
  reflecting the product's core metaphor (what you think you know vs.
  what's actually there).

## Known limits of this prototype

- All data is mocked; no persistence between sessions.
- No real authentication (login/register always "succeed").
- The diagnosis engine is not real AI yet — `knowledgeMirrorReport` is a
  fixed example. Wiring an LLM call into `POST /assessment/{topic_id}/submit`
  is the natural next step.
